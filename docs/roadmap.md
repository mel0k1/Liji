# Дорожная карта Liji

План движения от пустого репозитория до ОС, которую можно поставить на железо. Каждая фаза заканчивается проверяемым результатом — «сделано» означает, что результат воспроизводится на чистой машине по инструкциям в репозитории.

## Фаза 0 — Фундамент *(текущая)*

- [x] Репозиторий Liji, README, лицензия Apache-2.0
- [x] Скрипт выкачки исходников Fuchsia (`fetch_fuchsia.sh`)
- [x] Скрипт обрезки дерева исходников (`prune_fuchsia.sh`)
- [x] Архитектурный документ и дорожная карта
- [x] CI: проверка скриптов (shellcheck + синтаксис)
- [x] Проверочная выкачка `stem`-манифеста: механика подтверждена (jiri через CIPD, импорт `stem`, ~5,3 ГБ загружено до исчерпания диска тестовой песочницы); полный объём выкачки замеряется на целевой машине

**Результат:** любой желающий одной командой выкачивает урезанные исходники и понимает, что происходит дальше.

## Фаза 1 — Первая сборка

- [ ] Выкачка на целевой машине (stem; при нехватке частей — flower)
- [ ] `fx set core.x64 --release` и `fx build` без ошибок
- [ ] Запуск в QEMU/FEMU: консоль, `ffx` видит устройство
- [ ] Замер: объём выкачки, объём сборки, время сборки на референсном железе

**Результат:** работающий `core.x64` в эмуляторе, собранный из нашего checkout.

## Фаза 2 — Минимальный образ Liji

- [ ] Собственный GN-продукт `liji` на базе `core`
- [ ] Вырезка лишних компонентов из базового набора образа
- [ ] Загрузка образа: логотип загрузки, вход в систему, минимальная сессия-заглушка
- [ ] A/B-обновление образа в эмуляторе (OTA-механика)

**Результат:** образ, который грузится и обновляется; это уже «скелет настоящей ОС».

## Фаза 3 — Flutter runtime

- [ ] flutter runner в составе образа
- [ ] Первый Flutter-компонент в эмуляторе: окно с M3E-темой
- [ ] Связка Scenic ↔ Flutter: отрисовка, фокус, ввод с клавиатуры и мыши
- [ ] Механика установки приложений `.far` через pkg-resolver

**Результат:** на экране эмулятора — живой Flutter-интерфейс, принимающий ввод.

## Фаза 4 — Mejo MVP

- [ ] `mejo_shell`: компонент сессии по умолчанию в продукте `liji`
- [ ] `mejo_panel`: системная панель с часами и индикаторами
- [ ] `mejo_launcher`: запуск установленных Flutter-приложений
- [ ] `mejo_wm`: базовая компоновка окон, перетаскивание, фокус, Alt+Tab
- [ ] Анимации переходов в духе M3E (контейнерные трансформации)

**Результат:** в эмуляторе работает узнаваемый десктоп: панель, лаунчер, окна.

## Фаза 5 — Дизайн-система M3E

- [ ] `mejo_kit`: токены цвета/типографики/форм на базе M3E
- [ ] Динамические темы (в т.ч. из обоев), светлая/тёмная
- [ ] Библиотека компонентов: кнопки, карточки, шторки, диалоги, FAB
- [ ] Motion-киты: выразительные переходы, spring-анимации
- [ ] Настройки системы как M3E-приложение

**Результат:** у Mejo собственное лицо — целостный, выразительный Material 3 Expressive.

## Фаза 6 — Реальное железо

- [ ] Продукт `bringup`-уровня для x64 UEFI: NVMe/USB, GOP-видео, PS2/USB-HID
- [ ] Белый список тестовых машин (какие системы доступны)
- [ ] Звук и сеть на целевом железе
- [ ] ARM64-ветка (по мере зрелости x64)

**Результат:** Liji грузится на реальных компьютерах из белого списка.

## Риски

| Риск | Влияние | Стратегия |
|---|---|---|
| Драйверы железа | Высокое | QEMU сначала; белый список железа; DFv2-драйверы по мере сил |
| Flutter/Fuchsia API нестабильны | Среднее | Фиксация ревизий выкачки, осознанные апгрейды |
| Объём сборки | Среднее | stem + prune + продуктовая конфигурация; диск 100+ ГБ |
| Усилия одного разработчика | Высокое | Малые проверяемые фазы, воспроизводимые инструкции, ранняя документация |
